# 노션 포트폴리오 동기화

**명령 하나로 끝낸다. 파일을 읽거나 단계를 손으로 나누지 말 것 — 토큰·시간 낭비.**

```bash
bash scripts/sync-deploy.sh $ARGUMENTS
```

증분 동기화 → 이미지 치수 → 빌드 검증 → 동기화 산출물만 커밋 → `pull --rebase` → 푸시(Vercel 자동 배포). 노션 변경이 없으면 "변경 없음"으로 조기 종료.

## 할 일

1. 위 명령을 **한 번** 실행한다. 평소 20초 안팎(새 사진만 받음). 새 현장이 여러 개면 길어질 수 있으니 그땐 `run_in_background`.
2. 마지막 요약 줄(`✓ …`)을 사용자에게 그대로 전달한다.
3. 로그 재분석·seed 열람·빌드 재실행 금지. 스크립트가 이미 검증했다.

## 공개 여부 = 노션 `공홈 업로드` 체크박스

- 체크된 현장만 사이트에 나간다. 해제 → 다음 동기화 때 목록·상세·이미지 모두 제거.
- 사진이 0장인 현장은 체크돼 있어도 건너뛴다.
- 현장 번호(URL)는 `scripts/.no-map.json`에 고정 — 해제했다가 다시 체크해도 같은 주소로 복귀.
- "공홈에서 내려줘/올려줘" 요청은 노션에서 해당 행의 체크를 바꾼 뒤 이 스킬을 실행한다.

## 옵션

| 인자 | 동작 |
|---|---|
| `--dry` | 무엇이 바뀌는지만(다운로드·커밋 없음). 비공개 전환 목록도 보여준다 |
| `--no-push` | 커밋까지만 |
| `--force` | 증분 무시 전체 재다운로드(이미지가 깨졌을 때만, 오래 걸림) |
| `--yes` | 비공개 전환이 5건 초과여도 진행 |

## 실패 시

- `✗ N건이 한꺼번에 사이트에서 빠집니다` → 목록을 사용자에게 보여주고 의도 확인 후 `--yes`로 재실행.
- `You have not agreed to the Xcode license` → git이 막힌 것. 사용자가 `sudo xcodebuild -license accept` 실행 후 재시도(다운로드분은 재사용됨).
- `✗ 빌드 실패` → 출력된 로그로 원인 수정 후 재실행.
- `.env.local`에 `NOTION_TOKEN` 필요(없으면 스크립트가 즉시 알림).
