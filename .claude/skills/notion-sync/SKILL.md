# 노션 포트폴리오 동기화

**단 하나의 명령으로 전 과정을 실행한다. 파일을 다시 읽거나 단계를 손으로 나눠 하지 말 것 — 토큰·시간 낭비다.**

```bash
bash scripts/sync-deploy.sh
```

이 스크립트가 순서대로 처리한다: 증분 동기화(변경분만 다운로드) → 새 이미지 치수 보정 → 빌드 검증 → 시크릿/대용량 스테이징 차단 → 커밋 → 푸시(Vercel 자동 배포). **노션에 변경이 없으면 아무것도 커밋하지 않고 "변경 없음"으로 조기 종료**한다.

## 해야 할 일

1. 위 명령을 **그대로 한 번** 실행한다.
2. 스크립트의 **마지막 요약 줄(`✓ …`)을 사용자에게 그대로 전달**한다. 재사용/새로받음/정리 개수가 거기 담겨 있다.
3. 그 외 로그를 다시 분석하거나, seed·이미지를 직접 열어보거나, 빌드를 또 돌리지 말 것. 스크립트가 이미 검증했다.

## 옵션 (요청에 맞을 때만)

- 미리보기(무엇이 바뀌는지만, 다운로드·배포 없음): `bash scripts/sync-deploy.sh --dry`
- 배포 없이 커밋까지만: `bash scripts/sync-deploy.sh --no-push`
- 증분 무시하고 전체 재다운로드(오래 걸림, 이미지가 깨졌을 때만): `bash scripts/sync-deploy.sh --force`

## 배포 확인 (실제로 푸시했을 때만, 선택)

요약이 "배포 완료"면 1~2분 뒤 아래로 확인할 수 있다(`age`가 낮아지면 새 배포):

```bash
curl -sI https://plano-site.vercel.app/portfolio | grep -i age
```

변경이 없어 조기 종료했거나 `--dry`였다면 이 확인은 불필요하다.

## 전제 / 주의

- `.env.local`에 `NOTION_TOKEN`이 있어야 한다(없으면 스크립트가 즉시 알려준다).
- 스크립트가 `.env`·`포트폴리오/` 스테이징을 자동 차단하고, 빌드 실패 시 커밋을 중단한다 — 별도 안전 점검을 손으로 반복하지 말 것.
- 세부 배경은 [CLAUDE.md](../../../CLAUDE.md)의 "데이터 흐름" 참고.
