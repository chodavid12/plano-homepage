# Notion DB 구성 가이드 (팀용)

사이트와 자동 동기화되는 Notion 데이터베이스를 만드는 방법. 이 명세대로 속성을 만들면 사이트가 그대로 읽어간다.

> 핵심 규칙: **`홈페이지 노출` 체크박스가 켜진(`✓`) 행만 사이트로 나간다.** 작업 중이거나 비공개로 둘 프로젝트는 체크하지 않으면 된다.

---

## 1. `Portfolio` DB — 프로젝트 1행 = 1프로젝트

| 속성명 | 타입 | 필수 | 설명 / 예시 |
|---|---|:---:|---|
| **No** | Number (또는 Title) | ✅ | 프로젝트 넘버. 상세 URL과 `NO.###` 표시에 사용. 예: `421` |
| **제목** | Text | ✅ | 프로젝트명. 예: `淸輝齋`, `Sequentopia` |
| **아파트** | Text | | 서브타이틀(단지/건물명). 예: `용산파크타워` |
| **평형구분** | Select | ✅ | 목록 필터용. 값: `10PY` `20PY` `30PY` `40PY` `50PY~` |
| **유형** | Select | | `주상복합` `아파트` `오피스텔` `단독주택` 등 |
| **면적-공급** | Text | | 예: `47.97평형` |
| **면적-전용** | Text | | 예: `37.75평` |
| **준공연도** | Number | | 예: `2009` |
| **지역** | Text 또는 Select | | 예: `서울시 용산구 용산동` |
| **기간** | Text | | 시공 기간. 예: `11주` |
| **대표이미지** | Files & media | ✅ | 목록 카드 커버. 1장 권장 |
| **홈페이지 노출** | **Checkbox** | ✅ | **이 체크박스가 켜진 행만 사이트로 동기화된다.** |
| **노출순서** | Number | | 목록 정렬 기준(작을수록 먼저). 비우면 No 기준 정렬 |

### 운영 팁
- 새 프로젝트를 준비 중일 땐 `홈페이지 노출`을 **꺼둔 상태**로 작성하고, 완성되면 체크한다.
- 사이트에서 내리고 싶으면 행을 지우지 말고 **체크만 해제**해도 된다(데이터 보존).

## 2. `Portfolio Images` DB — 갤러리(프로젝트당 여러 행)

상세 페이지의 **공간별 탭**과 **이미지 캐러셀**을 구성하는 이미지 모음.

| 속성명 | 타입 | 필수 | 설명 |
|---|---|:---:|---|
| **프로젝트** | Relation → `Portfolio` | ✅ | 어떤 프로젝트의 이미지인지 연결 |
| **공간** | Select | ✅ | 탭 이름이 됨. 값 예: `거실` `주방` `복도` `현관` `욕실` `드레스룸` `서재` |
| **이미지** | Files & media | ✅ | 해당 공간 사진(여러 장이면 행을 나눠 추가) |
| **순서** | Number | | 같은 공간 내 표시 순서 |

### 운영 팁
- "공간" Select 값이 **상세 페이지 탭으로 그대로 노출**된다 → 일관된 명칭을 사용한다(예: `거실`/`리빙` 혼용 금지).
- 한 공간에 사진이 여러 장이면 **행을 여러 개** 만들고 `순서`로 정렬한다.

> 대안: 별도 Images DB 대신 프로젝트 본문에 공간별 헤딩+이미지를 넣는 방식도 가능하나,
> **별도 Images DB가 업로드·정렬·탭 매핑이 가장 명확**해 권장한다.

## 3. 상담 응답 DB (기존 운영 중인 노션 폼의 응답 DB)

사이트 `/consultant` 커스텀 폼이 제출되면, Notion API가 이 DB에 **새 행을 생성**한다.
아래 속성을 갖추면 폼 입력이 그대로 매핑된다(속성명은 팀 현행에 맞춰 조정 가능).

| 속성명(예시) | 타입 | 매핑되는 폼 입력 |
|---|---|---|
| **이름** | Title | 신청자 이름 |
| **연락처** | Phone 또는 Text | 전화번호 |
| **희망 평형** | Select 또는 Text | 평형 |
| **지역** | Text | 희망/현재 지역 |
| **예산** | Text 또는 Number | 예산 |
| **문의내용** | Text | 메시지 |
| **유입경로** | Select | (선택) 홈페이지 등 |
| **접수일시** | Created time | 자동 |
| **상태** | Select | (선택) `신규` `상담중` `완료` |

---

## 4. 연동을 위해 필요한 값 (개발자 전달)

각 DB를 만든 뒤 아래 값을 개발자에게 전달하면 사이트에 연결된다.

| 항목 | 어디서 얻나 | 환경변수 |
|---|---|---|
| Notion 통합(Integration) 토큰 | notion.so/my-integrations 에서 생성 후 각 DB에 "연결" | `NOTION_TOKEN` |
| Portfolio DB ID | DB 페이지 URL의 32자리 ID | `NOTION_PORTFOLIO_DB_ID` |
| Portfolio Images DB ID | 〃 | `NOTION_IMAGES_DB_ID` |
| 상담 응답 DB ID | 〃 | `NOTION_CONSULT_DB_ID` |

> Integration을 만든 뒤, **각 DB의 우측 상단 `···` → 연결(Connections)** 에서 해당 Integration을 추가해야
> API가 그 DB를 읽고 쓸 수 있다.

---

## 5. 사이트 반영 흐름 (참고)

1. 팀이 노션에서 프로젝트 작성 + `홈페이지 노출 ✓`
2. 동기화 잡(`/api/sync`)이 노출 체크된 행만 가져옴 → 이미지는 Supabase Storage로 복사
3. 사이트(목록/상세) 자동 갱신
4. (즉시 반영이 필요하면 노션 자동화/버튼으로 `/api/sync`를 바로 호출하도록 설정 가능)
