# PLANO 홈페이지 기획안 — 포트폴리오 + Notion 자동 동기화

작성일: 2026-06-23 · 대상: 플라노디자인(PLANO DESIGN) 공식 홈페이지

---

## 1. 배경 / 목적

- 기존 사이트 `https://planodesign.kr`(플라노디자인, 인테리어 스튜디오)를 **코드 기반으로 재구축**한다.
- 핵심 목표: **포트폴리오 콘텐츠를 Notion DB에서 관리하면 사이트가 자동으로 동기화**되도록 한다.
  팀이 코드를 건드리지 않고 노션에서 프로젝트를 추가/수정하면 사이트에 반영된다.
- 레퍼런스 UX는 인테리어 포트폴리오 사이트 패턴:
  1. **포트폴리오 목록** — 평형 필터 + 검색이 있는 2단 카드 그리드
  2. **포트폴리오 상세** — 메타데이터 + 공간별(거실/주방/…) 탭 + 이미지 캐러셀 + 상담 CTA
- 메인 페이지는 **미니멀 스플래시형**: 풀스크린 인테리어 배경 + 중앙 로고 + `PORTFOLIO` / `CONSULTANT` 버튼.

### 확정된 의사결정

| 항목 | 결정 |
|---|---|
| 프레임워크 / 호스팅 | **Next.js + Tailwind + Vercel** |
| 콘텐츠 원본 | **Notion = source of truth** (사이트 자동 동기화) |
| 이미지 캐시 | **Supabase Storage** |
| 동기화 범위 | 노션 전체가 아니라 **체크박스 `홈페이지 노출 ✓` 인 행만** |
| 메뉴(GNB) | **ABOUT · PORTFOLIO · CONSULTANT** (3개) |
| 메인 배경 | **고정 이미지 1장**(코드에 고정, 노션 동기화 대상 아님) |
| 랜딩 헤더/푸터 | **최소화**(랜딩에선 숨김, 내부 페이지에서 노출) |
| 상담(CONSULTANT) 폼 | **커스텀 폼 → Notion API** (기존 노션 상담 응답 DB에 적재) |
| 이번 산출물 | **기획안 문서만** (구현은 후속 단계) |

### 기술적 전제 (중요)

> Notion API가 반환하는 이미지 URL은 **약 1시간 후 만료**된다.
> 따라서 "자동 동기화"는 단순 API 호출이 아니라, **이미지를 Supabase Storage로 복사(캐싱)**해
> 만료되지 않는 안정 URL로 제공하는 파이프라인을 반드시 포함해야 한다.

## 2. 홈페이지 구성 (Information Architecture)

### 2.1 사이트맵

글로벌 메뉴(GNB) = **ABOUT · PORTFOLIO · CONSULTANT**

```
/                      메인 — 풀스크린 스플래시(로고 + PORTFOLIO·CONSULTANT 버튼)
/about                 ABOUT — 회사소개(브랜드 스토리 · 프로세스)
/portfolio             PORTFOLIO — 포트폴리오 목록
  ?view=project        └ 프로젝트별로 보기 (기본)
  ?view=space          └ 세부 공간별로 보기 (거실/주방/…별 브라우징)
  ?size=10PY|20PY|…    └ 평형 필터 (전체 / 10 / 20 / 30 / 40 / 50PY~)
  ?q=                  └ 검색 (아파트명 · 지역 · 넘버)
/portfolio/[no]        포트폴리오 상세
/consultant            CONSULTANT — 상담신청(커스텀 폼 → Notion API)
전역                    플로팅 "1:1 문의" 버튼 · 전체메뉴(그리드 아이콘)
```

### 2.2 화면별 구성

#### 공통 레이아웃
- **GNB**: 로고(PLANO), 메뉴 `ABOUT · PORTFOLIO · CONSULTANT`, 전체메뉴(그리드 아이콘 → 드로어)
- **Footer**: 사업자정보, 연락처, SNS(인스타 `@planodesign.kr`), 약관
- **플로팅 `1:1 문의` 버튼**(우하단), 모바일 햄버거 메뉴

#### 메인 `/` — 미니멀 스플래시형
- **풀스크린 히어로**: 인테리어 배경 이미지(따뜻한 우드/화이트 톤) 위 옅은 어두운 오버레이
- 중앙: **PLANO DESIGN 로고**(D 북마크 심볼 + 워드마크), 흰색
- 하단 중앙: 버튼 2개 — `PORTFOLIO →`(→ `/portfolio`), `CONSULTANT →`(→ `/consultant`)
- **랜딩에선 GNB·푸터 미표시**(투명/숨김), 내부 페이지 진입 후 헤더 노출
- 배경은 **고정 이미지 1장**(`public/` 에셋, 코드 고정). 별도 섹션·그리드 없음

#### 포트폴리오 목록 `/portfolio`
- 탭: `프로젝트별로 보기` / `세부 공간별로 보기`
- 평형 필터 칩: `전체 ✓ / 10PY / 20PY / 30PY / 40PY / 50PY~`
- 검색창: "아파트명(지역명) 또는 넘버 검색"
- 2단 카드 그리드: 대표 이미지 + `NO.### | 제목` + `아파트명 ##평형`
- 페이지네이션 또는 무한스크롤, 모바일 1단
- **세부 공간별 보기**: 같은 데이터를 공간(거실/주방/…) 기준으로 묶어 브라우징, 각 이미지는 해당 프로젝트 상세로 연결

#### 포트폴리오 상세 `/portfolio/[no]`
- 타이틀(`NO.### | 제목`) + 서브타이틀
- 메타 테이블: `유형 · 면적(공급/전용) · 준공 · 지역 · 기간`
- **공간별 탭**(동적): `거실 / 주방 / 복도 / 현관 / 욕실 / 드레스룸 / 서재 …`
- 썸네일 스트립 + 메인 이미지 캐러셀(이전/다음, 모바일 스와이프)
- 하단: `다음` 프로젝트 · `목록보기`

#### ABOUT `/about`
- 브랜드 스토리, 디자인 철학, 시공 프로세스, (선택) 팀 소개

#### CONSULTANT `/consultant` — 커스텀 폼 → Notion API
- 사이트에 **브랜드 톤 커스텀 폼**: 이름 · 연락처 · 희망 평형 · 지역 · 예산 · 문의내용 등
- 제출 → `/api/consult`(서버) → **Notion API로 기존 상담 응답 DB에 행 생성** → 노션에서 응답 관리(현행 유지)
- 부가: 제출 알림(메일/슬랙) 옵션, 스팸 방지(허니팟 + 레이트리밋), 제출 완료 화면
- 응답이 노션에 적재되므로 Supabase에는 별도 상담 테이블을 두지 않음

### 2.3 반응형 / 접근성
- 데스크탑 2단 그리드 / 모바일 1단, 헤더 햄버거, 캐러셀 터치 스와이프
- 시맨틱 마크업, 키보드 내비게이션, 이미지 `alt`

## 3. 기술서 (Technical Specification)

### 3.1 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Next.js (App Router, TypeScript)** | SSG/ISR, SEO |
| 스타일 | **Tailwind CSS** + 디자인 토큰 | 베이지/화이트 미니멀 톤, Pretendard(국문) |
| 데이터/스토리지 | **Supabase** (Postgres + Storage) | 동기화 캐시 + 이미지 CDN |
| CMS 원본 | **Notion** (`@notionhq/client`) | 팀 업로드 = 원본 |
| 이미지 | `next/image` + Supabase URL, 동기화 시 `sharp`로 webp 변환 | 만료 없는 안정 URL |
| 호스팅 | **Vercel** (+ Vercel Cron) | 자동배포, 스케줄 동기화 |
| 상담 폼 | 커스텀 폼 → `/api/consult` → **Notion API** 응답 DB 기록 (+Resend/Slack 알림) | 응답은 노션에서 관리 |

### 3.2 아키텍처 — Notion → Supabase → Next.js

```
[Notion 포트폴리오 DB]  ← 팀이 업로드/편집 (원본)
        │  동기화 트리거: ⓐ Vercel Cron(주기)  ⓑ 온디맨드 웹훅(/api/sync, 시크릿)
        ▼
[/api/sync 동기화 잡]
   1. Notion DB 조회 — 필터: 체크박스 `홈페이지 노출 = true` 인 행만 (전체 X)
   2. last_edited_time 비교로 변경분만 처리(증분)
   3. 이미지: Notion 임시 URL → 다운로드 → webp 변환 → Supabase Storage 업로드(안정 URL)
   4. 메타데이터 upsert, 체크 해제/삭제분 정리
   5. 완료 후 Next.js revalidateTag('portfolio') 호출
        ▼
[Supabase: projects / project_images / Storage]  ← 사이트가 읽는 단일 소스
        ▼
[Next.js (Vercel)]  포트폴리오 페이지를 Supabase에서 SSG/ISR로 렌더 (Notion 직접 호출 X)
```

- **핵심 원칙**: 사이트는 런타임에 Notion을 호출하지 않고 **Supabase만** 읽는다 → 빠르고, 이미지 URL 만료·요청 제한 영향이 없다.
- 상세 페이지: `generateStaticParams`를 Supabase에서 생성, 태그 기반 On-Demand ISR.

> 다이어그램 상세 버전은 [`architecture.md`](architecture.md) 참고.

### 3.4 Supabase 스키마

- **`projects`**: `id, notion_page_id(unique), no, title, subtitle, apartment, size_category, type, area_supply, area_exclusive, completion_year, region, period, cover_url, sort_order, notion_last_edited_at, created_at, updated_at`
  - Supabase에는 **노출 체크된 행만** 존재 → 별도 status 컬럼 불필요. 체크 해제 시 동기화 잡이 삭제.
- **`project_images`**: `id, project_id(fk), room, image_url, storage_path, sort_order, source_id`
- 상담 응답은 Supabase가 아닌 **Notion 응답 DB**에 저장 → `inquiries` 테이블 없음
- **Storage 버킷** `portfolio`(public): `projects/{notion_page_id}/{room}/{hash}.webp`
- **RLS**: `projects` / `project_images` public read

### 3.5 동기화 상세

- **필터(핵심)**: Notion DB 쿼리 시 `홈페이지 노출(Checkbox) = true` 조건으로만 조회 → 노션 전체가 아니라 노출 체크된 행만 반영
- **트리거**:
  - ⓐ **Vercel Cron**(예: 10~30분 주기) → `/api/sync`
  - ⓑ **온디맨드** — Notion 자동화/버튼이 시크릿 헤더로 `/api/sync` 호출(즉시 반영)
- **증분 처리**: `notion_last_edited_at` 비교, 변경된 행·이미지만 재다운로드
- **이미지**: 다운로드 → `sharp` webp 변환 → Supabase 업로드 → URL을 DB에 저장(콘텐츠 해시로 중복 방지)
- **정리**: `홈페이지 노출` 체크 해제 또는 행 삭제 → Supabase·Storage에서 제거(사이트에서 내려감)
- **반영**: 동기화 종료 시 `revalidateTag('portfolio')`로 목록·상세 갱신

### 3.6 상담 폼 처리 (CONSULTANT)

- 클라이언트: 커스텀 폼 컴포넌트(검증, 로딩/성공/실패 상태)
- 서버: `POST /api/consult` → 입력 검증 → `@notionhq/client`로 **상담 응답 DB(`NOTION_CONSULT_DB_ID`)에 페이지 생성**
- 노션 응답 DB 속성에 폼 필드를 매핑(이름/연락처/평형/지역/예산/문의내용/유입경로 등)
- 부가: Resend(메일) 또는 Slack Webhook 알림, 허니팟 + 레이트리밋으로 스팸 방지

### 3.7 환경변수 (.env)


### 3.8 비기능 요구

- **반응형**: 데스크탑 2단 / 모바일 1단, 캐러셀 터치 스와이프
- **SEO**: 메타데이터 / OG 이미지 / sitemap / robots, `ko` 로케일, 정적 렌더로 LCP 최적화
- **접근성**: 시맨틱 마크업, 키보드 내비, 이미지 `alt`
- **분석(선택)**: Vercel Analytics 또는 GA4

## 5. 검증 (Verification)

- 본 문서 + Notion 스키마 + 아키텍처 문서가 홈페이지 구성(IA), 기술서, 자동 동기화, DB 스키마를 모두 포함하는지 확인
- (후속 구현 시) 각 단계는 로컬 `next dev` + Supabase 시드 데이터로 목록/상세 렌더 및 동기화 잡 동작을 검증
- 동기화 검증 시나리오:
  1. 노션에서 `홈페이지 노출` 체크 → `/api/sync` → 사이트 목록에 등장
  2. 체크 해제 → 동기화 → 사이트에서 사라짐
  3. 이미지 추가/교체 → Supabase Storage에 webp로 캐싱되고 상세 캐러셀에 반영
  4. `/consultant` 폼 제출 → 노션 상담 응답 DB에 행 생성
